# 运维、成本与上线验收

## 当前价格口径

以下是 2026-11-11 核对的 Cloudflare 官方公开价格，实际账单以账号套餐和官网实时价格为准。

| 项目 | 小规模预算 | 说明 |
|---|---:|---|
| 域名 | 约 US$10–20/年 | `.com` 的粗略市场预算；后缀与注册商不同会变动 |
| Email Routing 入站 | US$0 | 官方说明入站邮件在 Workers Free/Paid 均不限量；处理仍占 Worker 资源 |
| Workers | 免费档或最低 US$5/月付费档 | 免费档每天 10 万请求、每次 10 ms CPU；复杂邮件处理可能需要付费档 |
| D1 | 免费档含 5 GB | 免费档还有每日读写行数限制；本项目只把元数据放 D1 |
| R2 标准存储 | 免费档含 10 GB·月 | 免费档另含每月 100 万次 A 类、1000 万次 B 类操作；超过后按用量计费 |

例如每月 1000 个客户、每客户 2 封邮件、每封平均 100 KB，新增原文约 200 MB；如果按用餐日期及时清理，通常远低于 R2 免费存储量。真实占用还会受附件、垃圾邮件和保留时间影响。这个预算**不包括开发人力、原抢票项目代理/打码费用、域名购买及业务平台交付开发**。

官方来源：[邮件价格](https://developers.cloudflare.com/email-service/platform/pricing/)、[邮件限制](https://developers.cloudflare.com/email-service/platform/limits/)、[Workers 价格](https://developers.cloudflare.com/workers/platform/pricing/)、[D1 价格](https://developers.cloudflare.com/d1/platform/pricing/)、[R2 价格](https://developers.cloudflare.com/r2/pricing/)。

## 配额与容量

- Cloudflare Email Routing 当前入站单封邮件最大 25 MiB；本项目默认拒收超过 1 MiB 的邮件，可通过 `MAX_MESSAGE_BYTES` 提高，但应先测真实邮件和 Worker CPU。
- 单邮箱默认最多 50 封，达到上限后拒收。宝可梦确认信通常远少于该值，但应为异常重发和售后邮件留余量。
- Catch-all 会让任意地址先到 Worker；未知地址会被拒收，已知地址仍可能收到垃圾邮件，需监控数量。
- 免费档达到 Worker/D1 限制后可能直接失败；正式业务可优先预算 US$5/月的 Workers Paid，以减少 CPU 限额风险，并设置支出告警。
- Cron 每小时触发。大批量过期时分批清理，可能多轮才完成；**登录和收信失效不依赖 Cron**。

## 每日监控

| 信号 | 正常情况 | 异常时检查 |
|---|---|---|
| 邮件处理失败 / `setReject` 增加 | 已创建邮箱能收到邮件 | MX、Routing Worker、邮箱状态、大小/数量限制、D1/R2 错误 |
| 验证码查询耗时 | 在目标预约步骤允许的时间内出现 | 官方发件地址、`since`、MIME 格式、收信延迟 |
| 管理 API 5xx | 接近 0 | Worker 绑定、D1/R2 可用性、资源配额 |
| 客户登录失败/锁定 | 偶发 | 密码交付、是否重复签发、时区与到期时间 |
| 清理积压 | 到期后按宽限清除 | Cron 是否触发、R2 删除异常、每轮处理上限 |
| R2 占用增长 | 随订单量波动并清理 | 垃圾邮件、附件、过期地址、残留对象 |

Worker 日志只记录错误类型，不记录邮件正文、验证码、客户密码和管理员密钥。业务侧也应做到同样的日志脱敏。

## 故障处理

1. **邮件未到**：先查域名 MX 与 Email Routing 状态，再查 Worker 日志、邮箱是否仍 `active`、收件地址是否精确一致、是否超过大小/数量限制。外部普通邮件可到而宝可梦邮件不到时，检查官方是否拒绝此域名或投递有延迟。
2. **验证码接口 404**：查该邮箱的 `/messages`。无邮件属于投递问题；有邮件则查 `since`、发件地址和邮件格式。不要无期限轮询。
3. **客户不能登录**：查邮箱 `expiresAt`、`credentialsIssued`，并确认交付后没有再次调用 `/credentials`。5 次失败会锁定 15 分钟。
4. **误停用**：当前版本没有恢复接口；若邮件尚未被清理，可由管理员备份后人工处理。正常运营应把 `/disable` 调用限制在明确的业务终态。
5. **数据库或对象存储故障**：停止新订单专属邮箱的分配；先修复存储，再重试创建与收信。D1 元数据和 R2 原文须成对备份与恢复。
6. **密钥泄露**：轮换 `ADMIN_API_KEY` 并审计创建/停用记录。轮换 `AUTH_PEPPER` 会使全部客户密码和会话失效，需要逐邮箱重签发并重新交付。

## 上线门槛

- [ ] 真实域名 MX 和 Catch-all 路由已验证；未知地址被拒收。
- [ ] 宝可梦官方验证码、确认邮件均能送达；记录实际延迟与大小。
- [ ] 手机端登录能看清官方发件人、预约姓名/番号和日期；现场展示方式已确认可接受。
- [ ] 客户密码只在成功后交付一次，普通日志与飞书没有密码/API 密钥。
- [ ] 两个订单不能互看邮件；旧密码、旧会话在重新签发或停用后失效。
- [ ] 邮箱到期立即不能登录/收信，Cron 随后清理 D1 与 R2。
- [ ] 已设置 Cloudflare 用量、Worker 错误和清理失败的告警。
- [ ] 已演练 D1/R2 备份与恢复；备份保留期符合你的删除承诺。
