# 安全与数据处理

本项目接触客户姓名关联的预约邮件、邮箱密码和验证码。上线前应把本文件作为检查清单，与业务平台的隐私说明和数据保留规则对齐。

## 凭证分离

- `ADMIN_API_KEY` 只能存在于抢票后台或安全的管理环境，不能给客户或前端。建议额外限制管理接口的来源，例如 Cloudflare Access 服务令牌或网络访问规则。
- `AUTH_PEPPER` 只存在于 Worker Secret。客户密码是系统随机生成的高熵字符串，D1 中只保存 HMAC-SHA256 摘要；这套设计**不接受客户自行设置的弱密码**。如果以后开放自定义密码，须改用 Argon2id 等专用慢哈希。
- 客户密码在预约成功时签发、只返回一次。交付页应受原平台订单身份保护，禁止在 URL 参数、日志、埋点、飞书或客服群中传播密码。
- 登录会话是随机令牌，D1 只保存摘要；Cookie 使用 `HttpOnly`、`SameSite=Strict`，线上 HTTPS 还设置 `Secure`。每次读信都重新确认邮箱未过期、未停用。

## 邮件隔离与网页安全

- 每条消息带 `mailbox_id`；客户读取详情必须同时匹配当前会话邮箱，不能只按邮件 ID 查询。
- 页面将邮件内容写入 `textContent`，不执行邮件 HTML。对 HTML-only 邮件仅提取文本。`.eml` 原文作为附件下载，不在页面直接当 HTML 打开。
- 页面设置 CSP、禁止被其他网页嵌入、禁用缓存与 MIME 嗅探。状态变化和退出会撤销会话。
- 客户密码错误 5 次后锁定 15 分钟。Cloudflare 侧还可加 IP 速率限制，以减轻分布式猜测和接口滥用。
- 地址本地部分为随机字符串；不要使用客户姓名、手机号、日期或订单号生成可猜地址。

## 入站邮件与验证码

- 邮件服务只接收 `MAIL_DOMAIN` 下已创建、未过期的地址；未知地址和超限邮件拒收。Catch-all 不意味着公开任意收件箱。
- 验证码接口要求 `since`，只扫描该邮箱最近邮件并精确匹配官方发件地址。`From` 字段仍可能被伪造；若威胁模型要求验证发件真实性，应进一步检查入站身份验证结果（SPF/DKIM/DMARC）并做真实样本测试。
- 服务端不在日志中输出验证码、邮件正文或密码。原 `pokemon_cafe` 项目里涉及邮箱密码和 IMAP 授权码的日志/结果字段，接入新通道时必须脱敏。

## 到期与删除的准确含义

`expiresAt` 一到，客户登录、已有会话读信和新邮件接收都会立即失败。Cron 在 `purgeAt` 之后删除邮件原文和数据库记录。Cron 可能因错误或单轮上限而延后物理删除，应监控积压并重试。

Cloudflare 平台自身的备份、日志与恢复保留周期需要按其产品条款单独核对；“业务数据库/R2 删除”不应被宣传为所有副本瞬时不可恢复。客户已下载或截图的邮件也无法通过到期停用撤回。

## 生产密钥与权限

- 不在 Git 中提交 `.dev.vars`、`.env`、生产 API 密钥或客户密码。
- Cloudflare 控制台权限按最小范围授予；部署与日常业务调用使用不同凭证。
- D1 与 R2 备份应加密、限制访问，并设置明确的保留期。
- 定期检查管理 API 访问、重复创建、反复签发密码、异常停用与大量拒收事件。
